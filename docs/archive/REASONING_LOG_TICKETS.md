# Per-stage reasoning log — implementation tickets

## Context

Idea's adversarial transcript (`idea_maker`↔`idea_hater`) already has a real, shipped frontend treatment: a collapsible card in the conversation thread, a matching section in `IdeaFullPage.tsx`, and an Overview/Discussion tab pair in the Right Panel — all three surfaces reading the same parsed transcript (`parseIdeaLog()` in `parsers.ts`, rendered via `src/components/molecules/IdeaTranscript/IdeaTranscript.tsx`). See `Denario/.claude` memory `project_denario_status.md` for the full writeup (commit `dc5e158`).

That shipped version only covers Idea's **Fast track** (`idea_generation_output/idea.log`, a flat `\begin{IDEA}`/`\begin{CRITIC}` text log written by Denario's own LangGraph streaming code — confirmed via source, not cmbagent). The plan going forward, per the user, is to build the equivalent for other stages "that allow it," one at a time. Methods is next — and its real data shape (confirmed 2026-07-20 against a live Rigorous run) turned out richer and structurally different from Idea's, not a drop-in reuse.

## Ticket 1 — Design the frontend for Methods' Rigorous-track reasoning log *(Design ticket — not yet started; scope/approach not decided)*

**Description:** Methods' Rigorous track (`denario/method.py`'s `develop_method()`, via `cmbagent.planning_and_control_context_carryover(..., work_dir=method_dir)`) produces **two distinct real log sources**, confirmed against an actual run (project `acf2245e-4ef9-43fd-9f26-23aca22581a8`, `method_generation_output/` — note the real directory is singular **`method_generation_output`**, not plural, despite `idea_generation_output`/`experiment_generation_output` both being singular-stage-name-plus-suffix too; don't assume the naming pattern generalizes without checking):

1. **Planning phase** — `planning/chats/chat_output_planning.json`. A genuine adversarial loop structurally analogous to Idea's `idea_maker`↔`idea_hater`, just different agent names: `planner` proposes a plan → `plan_reviewer` critiques it (real example: *"Recommendations: In Step 1, add a bullet instructing the researcher..."*) → `planner` revises ("Updated Plan: ..."). List of message dicts (`{name, content, timestamp, cost}`); only `planner`/`plan_reviewer` entries have real content, everything else (`plan_setter`, `_Group_Tool_Executor`, `*_recorder`, `terminator`) is orchestration bookkeeping with `content: null` or a short status string.
2. **Execution phase** — `control/chats/chat_output_researcher_step_N.json`, one file per plan step (real example run had 3). Each file is a self-contained ~9-11-entry mini-transcript: `control`/`control_starter` (empty) → `_Group_Tool_Executor` (this step's briefing: step number, sub-task, instructions, sourced from the plan) → `researcher` (the real substantive markdown answer — this is the valuable content) → `researcher_response_formatter` (a JSON-structured echo of the same content) → `researcher_executor` (save confirmation) → repeats/previews the next step's briefing → `terminator` → "Session terminated." Only the `researcher`-named entries have real prose worth surfacing; everything else is noise to filter, same principle as Idea's `AdversarialLogCard` filtering to just `idea_maker`/`idea_hater`.

The plan overview itself — `planning/final_plan.json` — is clean structured data: `{ sub_tasks: [{ sub_task: string, sub_task_agent: string, bullet_points: string[] }] }`. Real example: 3 sub-tasks, all `sub_task_agent: "researcher"` (hypotheses/assumptions → econometric approach → final methodology write-up). This is the natural source for step titles/labels, parallel to how `IdeaTranscriptRound.round` numbers rounds today.

Also present but **out of scope for any UI** (not narrative content, not parseable from the frontend): `context/context_step_N.pkl` (Python pickle — cannot be read in JS at all), `*/cost/cost_report_*.json`, `*/time/timing_report_*.json` (cost/timing metadata, not reasoning — mirrors the decision already made for Idea to skip round-count-as-progress-%).

**Open design questions, genuinely undecided:**
- Two source types (a 3-turn planning debate + N sequential single-voice execution steps) don't map onto Idea's single flat round list — does this become one combined view (planning debate first, then step cards) or two separate sections/tabs? The existing `IdeaTranscriptCard`/`IdeaTranscriptRounds` components are Idea-specific (types, chip labels "IDEA"/"CRITIQUE") — decide how much to generalize vs. build Methods-specific siblings.
- Track detection: there is no persisted "which track did this stage use" field anywhere (checked `state.json` — no `track` key). Idea's shipped solution sidesteps this by just checking whether parsed content is non-empty and hiding the tab/section if not (`hasIdeaDiscussion` in `RightPanel.tsx`) — same pattern should carry over here (Fast-track Methods has confirmed zero log content, so the check naturally degrades correctly), but worth deciding explicitly rather than assuming.
- Whether/how to surface the plan-review loop's "Updated Plan" (the `planner`'s second, revised version) alongside the original — showing both, or just the final version with the reviewer's critique as context?
- A closely related, not-yet-confirmed gap: Idea's own Rigorous track almost certainly produces this exact same `planning`/`control/chats` structure (same underlying `cmbagent.planning_and_control_context_carryover()` call, just with `idea_maker_model`/`idea_hater_model` instead of `researcher`/`planner`/`plan_reviewer`) — meaning today's shipped Idea transcript feature (`idea.log`-only) would show nothing for a Rigorous-track Idea run. Not yet verified against real data (user is running this next) — whatever component design is chosen for Methods should be built with an eye toward also covering that case later, not hardcoded to Methods' specific agent names if avoidable.

**Files:**
- Backend (context/reference, not to be modified for a frontend-only ticket): `DenarioBackend/denario/method.py` (`develop_method()`), `DenarioBackend/denario/langgraph_agents/methods.py` (`methods_fast()` — confirmed no log output, single one-shot structured-output call)
- Frontend, existing pattern to extend or generalize: `Denario/src/components/molecules/IdeaTranscript/IdeaTranscript.tsx` (`IdeaTranscriptCard`, `IdeaTranscriptRounds`, `renderContent`/`renderBlock`/`renderInline` — the lightweight markdown/LaTeX renderer should be directly reusable as-is, since `researcher`'s content uses the same `##`/`**`/`` ` ``/`$math$` markdown family), `Denario/src/pages/StagePage/ConversationThread.tsx` (`AdversarialLogCard` — pattern to mirror for a Methods equivalent), `Denario/src/pages/StagePage/RightPanel.tsx` (Overview/Discussion tab pattern), `Denario/src/pages/MethodsFullPage/MethodsFullPage.tsx` (currently has **no** log section at all — unlike `IdeaFullPage.tsx`, which already had a placeholder before yesterday's work), `Denario/src/utils/parsers.ts` (`parseIdeaLog()` — pattern to mirror; a new `parseMethodsLog()`-equivalent will need to read JSON, not split on text delimiters), `Denario/src/utils/stageRunner.ts` (`fetchIdeaTranscript()` — pattern to mirror for fetching `method_generation_output/planning/chats/chat_output_planning.json` + `control/chats/chat_output_researcher_step_N.json` via the existing generic file route).

**Edge cases:**
- Number of execution steps is dynamic (plan-dependent, not always 3) — must read the actual count from `final_plan.json.sub_tasks.length` or by discovering how many `chat_output_researcher_step_N.json` files exist, not hardcode.
- A crashed/partial Rigorous run could leave some step files written and others missing — degrade gracefully (show what exists), same principle as Idea's `transcript.length > 0` gating, don't assume a complete set.
- `researcher_response_formatter`'s JSON-formatted echo of the researcher's content is redundant with the plain `researcher` entry — confirm only one is shown, not both (showing both would duplicate the same content in two different renderings).
- The generic file route (`GET /projects/{id}/files/{file_path:path}`) already serves arbitrary paths under the project directory — confirmed no new backend endpoint is needed to fetch any of these JSON files, same as was true for `idea.log`.

## Full pass over the remaining stages (2026-07-20) — which ones actually have a reasoning log to build

Ticket 1's open question — "does Idea's own Rigorous track produce this same structure?" — plus the broader "Methods/Analysis/etc. next, each needs its own log-format check" plan (see memory `project_denario_future_work.md`) prompted a source-level pass over every remaining stage's actual generation code in `DenarioBackend`, not assumption from the pattern established so far. Verified by reading the real dispatch code, not by running a fresh project (the one local project directory, `Denario/projects/52a46c9a-aa67-469d-8633-c0b40e3fbb92`, errored during Idea before writing any real log files — a local `cmbagent` env issue, not usable as live-run evidence here). Result: **two more stages get a real transcript, three don't — and CLAUDE.md's own stage descriptions turned out to be wrong on two counts, corrected below.**

### Ticket 2 — Idea's Rigorous-track reasoning log (open question from Ticket 1, now resolved)

**Confirmed:** `denario/idea.py`'s `develop_idea()` → `get_idea_cmagent()` path (`denario.py:319`) calls `cmbagent.planning_and_control_context_carryover()` (`idea.py:61`) — the exact same underlying call Methods' Rigorous track uses. This means Idea's Rigorous track produces the **same two-source `planning/chats` + `control/chats` JSON structure** documented in Ticket 1, not the flat `idea.log` text format.

**This confirms a real gap, not a hypothetical one:** the already-shipped Idea transcript feature (`parseIdeaLog()`, `IdeaTranscript.tsx`, commit `dc5e158`) only reads `idea_generation_output/idea.log` — which is written by the **Fast track** (`get_idea_fast()` → `langgraph_agents/idea.py`'s `idea_maker`/`idea_hater` node functions, confirmed distinct code path). A Rigorous-track Idea run today shows **no reasoning log at all** in the shipped UI, silently — `hasIdeaDiscussion` in `RightPanel.tsx` just evaluates false and hides the section, which reads as "no log exists" rather than "wrong parser for this track."

**Scope:** functionally the same ticket as Methods' Ticket 1 — reuse whatever component/parsing design gets picked for Methods' planning-debate-then-execution-steps shape, applied to Idea's Rigorous output directory instead. Do not build a second bespoke design; if Methods' design generalizes cleanly (open question already flagged in Ticket 1), this is the second consumer that proves it should.

**Files:** `DenarioBackend/denario/idea.py` (`develop_idea`, `get_idea_cmagent` — confirm the actual output directory name, likely `idea_generation_output/` matching the Fast-track directory reused for both tracks, not yet verified which); frontend files are the same list as Ticket 1, since this is the same parser/component work pointed at a different stage's directory.

### Ticket 3 — Analysis reasoning log — **decided against, not building this**

**Confirmed:** `denario/experiment.py`'s `Experiment.run_experiment()` also calls `cmbagent.planning_and_control_context_carryover()` (`experiment.py:85`) — same family as Methods and Idea's Rigorous track, so a log-viewer in the same shape was technically buildable.

**Decision (2026-07-20): skip it.** The per-step artifact is one large shared `control/chats/chat_history_step_N.json` file containing the full raw `chat_history` array — every orchestration message, not just the substantive ones — and unlike Methods (one real voice, `researcher`, per step), Analysis genuinely has two (`engineer` writing/executing code, `researcher` interpreting it; `denario.py:723`'s `get_results()` passes both `engineer_model` and `researcher_model` as real roles, and `involved_agents` doesn't actually constrain which one cmbagent invokes per step — it only flows into the planner's prompt text, `experiment.py:50-57`). That combination — a bigger raw transcript than Methods' already-heavy one, plus an unresolved question of whether a step's real content is one voice or two interleaved — pushes this well past "a debate a researcher would actually read." Reasoning was: a reasoning-log viewer only earns its keep if someone will actually read it; a wall of interleaved engineer/researcher chat turns clears that bar worse than Methods' single-voice version did, not better. Not deferred pending live-run verification — closed as a scope call, independent of whatever that verification would have shown.

**Left in place for the record, not to be picked back up without a reason to revisit:** the agent-roster/track findings below, since they're accurate regardless of this decision and were surfaced as CLAUDE.md corrections independent of whether Analysis gets a log viewer.

**Also confirmed, independent of the log question:** unlike Idea and Methods, **Analysis has no Fast/Standard track at all** — `get_results()` is the only path (no `get_results_fast()` exists in `denario.py`, and `api/runner.py`'s stage dispatch calls `den.get_results(...)` unconditionally regardless of the `track` request parameter). This was already corrected in `CLAUDE.md`'s "Dual tracks" line.

**Files (reference only — no longer an active ticket):** `DenarioBackend/denario/experiment.py` (`Experiment.run_experiment`), `denario/denario.py:723` (`get_results`).

### Ruled out — Paper, Literature, Referee, Keywords have no adversarial/planning transcript to show

Checked each stage's actual generation code rather than assuming the pattern generalizes to every remaining stage:

- **Paper** (`denario/paper_agents/paper_node.py` + `denario.py:864`'s `get_paper`) — no `cmbagent.planning_and_control_context_carryover()` call anywhere in `paper_agents/*.py`; the only `cmbagent` usage is a flat `cmbagent.get_keywords()` utility call (`paper_node.py:39`, unrelated to reasoning). Paper drafting is sequential per-section LLM calls with compile/fix retries (see `LATEX_EDITOR_TICKETS.md`'s Ticket 2 for that retry loop) — no debate, no plan, nothing shaped like a transcript. If "why did you write X in the manuscript" ever needs grounding, that's the Compose Bar's existing why-question mechanism (`COMPOSE_BAR_TICKETS.md`) reading drafting context on demand, not a transcript viewer.
- **Literature** (`denario/langgraph_agents/literature.py`) — a search/decide/summarize pipeline (`novelty_decider`, `semantic_scholar`/`SSAPI`, `literature_summary`), no cmbagent planning/control call, no second voice. If transparency is wanted here later, the natural shape is "which queries were run and why a given paper was judged similar/different" — a genuinely different feature, not a variant of the transcript pattern.
- **Referee** (`denario/langgraph_agents/referee.py`, 34 lines total) — **a single LLM call** (`reviewer_fast_prompt` → `LLM_call_stream`), reading the compiled paper's rendered pages as images and producing one review text. No track branching at all in `denario.py`'s `referee()` method (no Fast/Rigorous split, contradicting CLAUDE.md's blanket dual-track claim the same way Analysis does), and — separately — **CLAUDE.md's own description ("Simulates two independent peer reviewers") does not match the actual implementation**, which is one call producing one review, not two distinct reviewer voices. Nothing resembling a debate exists to log. Both CLAUDE.md discrepancies (Analysis's missing dual-track, Referee's single-reviewer reality) are worth fixing in that doc independent of this feature.
- **Keywords** (`denario.py:826`'s `get_keywords`) — a single `cmbagent.get_keywords()` utility call (`denario.py:839`). No planning, no log, already effectively confirmed by this being the pipeline's simplest stage.

**Net effect on the "each stage needs its own log-format check" plan:** the plan was right to check each one rather than assume — but the answer for four of the five remaining stages is "not building this," just for two different reasons. Paper/Literature/Referee/Keywords are closed out as structurally out of scope (no transcript exists to show). Analysis is closed out as a scope call (a transcript exists, but it's judged too large/noisy to be worth reading — see Ticket 3). **Idea's Rigorous track (Ticket 2) is the only remaining real addition** to the per-stage reasoning-log feature, alongside Methods' still-open Ticket 1.
